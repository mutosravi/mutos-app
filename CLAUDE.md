# Notes for Claude working on this repo

This is the **Muto's app** (repo mutosravi/mutos-app, Worker `mutos-app`, Supabase project "Mutos App" plbixpdyxpayyzpzrvna, later app.mutosstudio.com). It started as a copy of the season team app (mutosravi/mutos-team-app, frozen for the 2026–27 season, restore point branch `season-2026-live`). Build new studio departments here; never push studio features to mutos-team-app.

- The board is a single file, `src/shoot-board.html`, shared with the Claude-hosted artifact (it has no `<html>` wrapper). Never hand-edit `public/board.html`; edit the source and run `python3 tools/build-board.py`.
- App-only behaviour in the board is guarded by `window.MUTOS_APP` (Login Gmail field, `MUTOS_APP.attach(...)` after first load, `MUTOS_APP.changed()` after crew-relevant saves). The board must keep working with no `window.MUTOS_APP` and with the Claude runtime.
- `public/shim.js` implements `window.claude.use('db' | 'user')` on top of Supabase table `docs (collection, id, data jsonb)` with realtime; other capabilities return null.
- `public/crew-sync.js` builds each crew member's page with the board's `crewFeedFor(key)` and upserts `crew_feed`; the owner's board also keeps `members` (role crew) in step with the Login Gmail fields.
- Crew actions: `supabase/002_crew_actions.sql` (crew_away with a trigger that decides auto/pending, crew_status, push_subs). `public/team-updates.js` mirrors accepted crew dates into board `unavailability` with ids `crew-<uuid>` and shows the Team updates window. Reminders: `worker/index.js` (cron in `wrangler.jsonc`, secrets SUPABASE_SECRET_KEY + VAPID_PRIVATE_KEY), `public/sw.js`, `public/push-client.js`.
- Access rules live in `supabase/schema.sql` (RLS). Keep the owner email as the placeholder in the file.
- Gear desk: `supabase/003_gear_desk.sql` (role 'gear', gear_feed pushed by `crew-sync.js` pushGear, gear_log append-only), page `public/gear.html`.
- Team Alignment sync: the board's Drive call (`claude.use('mcp')`) is bridged in `shim.js` to `/api/team-sheet`, which reads the sheet with a service account (`worker/google.js`, secret GOOGLE_SERVICE_ACCOUNT; the sheet must be shared with it as Viewer).
- Backups: `worker/backup.js` (cron 30 21 UTC, KV binding BACKUPS; owner-only /api/backups routes; Backups window in `public/crew-sync.js`).
- Gear not-available dates: `eq.off = [{ d, n?, why }]` on equipment; `offUnits` is subtracted in `unitsFreeFor`, so pickers, conflicts and the Gear desk all follow it.
- Tests: `node tests/gear-off.test.js <backup.json>`, `node tests/reminders.test.mjs`, `node tests/team-sheet.test.mjs`, `node tests/team-sync.test.js <backup.json> <sheet-base64.txt>` (XLSX_JS=local xlsx.full.min.js if offline), `node tests/backup.test.mjs <backup.json>`, `node tests/undo.test.js <backup.json>`, `node tests/load-backup.test.js <backup.json>`, SQL `tests/rls_crew_actions.sql` and `tests/rls_gear_desk.sql` (after `tests/pg_stub.sql`, both schema files) and `node tests/app.test.js <dir with events/, shooters/, gear/ JSON exports>` (Playwright, fake Supabase that mirrors the RLS rules). All checks must pass before pushing.
- Owner preference: he is fine with being told when an idea is weak; suggest better options.
- Look (locked 5 Nov 2026, Blush & gold): `public/app.css` (Open Sans, tokens, tiles, bottom bar) for sign-in, crew and gear pages; `public/board-theme.css` restyles the board in the app only (build-board.py inlines it right after the board's own styles, so the Claude-hosted board keeps its dark look) and styles the owner header/Home. Icons: `public/icons.js` (`MUTOS_ICON(name)`).
- Home screens: owner/manager Home is `public/home.js` on board.html (header `#mutos-bar`, Home `#mutos-home`, phone bottom bar, More sheet); `#board` in the URL shows the board, otherwise Home. Tiles click the board's own buttons by id. The board passes extra helpers in `MUTOS_APP.attach` (isShort, inboxCount, openRentals, goToDate…). Crew and gear pages have Home/Shoots/Days off and Home/Day/Out now/Items/Log tabs (`.bnav .tab[data-tab]`).
- Board tests open `board.html#board`; app.test.js clicks the Shoots/Day tabs before using those screens.
- Logins: roles owner, manager, crew, gear, staff (office employee), accountant (prepares salaries), kiosk (office screen). `mutosApp.homeFor(role)` in `app-core.js` picks each one's first page. App name and logo are just "Muto's".
- Clients: `supabase/004_studio.sql` (client_links with a secret token, client_feed, client_itinerary; the page talks only through `client_get` / `client_save`, no login). Page `public/client.html?k=<token>`; owner/manager window `public/clients.js` (MUTOS_CLIENTS: make link, WhatsApp, see answers, Apply to board, add a new function as a shoot; keeps client_feed in step with the board). Home tile + "Needs you" card.
- Attendance & salary: same SQL (employees, att_settings, att_secret, att_punch via `att_punch()` which checks office location and the 6-digit office code server-side, att_requests with a trigger for advances ≤ one month's salary and fixes → punches, holidays, payroll_runs (accountant drafts, only the owner locks; locked never changes), payslips, att_log). Rules in `public/payroll.js` (MutosPay.monthCalc; decisions in project doc claude/attendance-and-salary.md). Pages: `work.html` (employee), `attendance.html` (owner + accountant), `office.html` (kiosk code screen). Shared loaders `att-data.js`.
- More tests: `node tests/payroll.test.js`, `node tests/studio.test.js <same data dir as app.test.js>`, SQL `tests/rls_studio.sql` (after the stub and schema, 002, 003, 004).
